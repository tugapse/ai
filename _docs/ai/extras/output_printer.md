## 1. Overview & Purpose
| Component | Source File |
| :--- | :--- |
| OutputPrinter | ai/extras/output_printer |

This component is responsible for controlling the output stream of tokens generated by a Large Language Model (LLM) based on a specified printing strategy. Its primary function is to buffer incoming tokens according to modes like 'line', 'every_x_tokens', or 'line_or_x_tokens', ensuring that output is presented to the console in a controlled, readable manner rather than printing every single token immediately.

Architecturally, `OutputPrinter` acts as a presentation layer utility, sitting between the core LLM generation logic and the console I/O. It relies on external functions from `ai.functions` to perform the actual printing, effectively managing the final rendering pipeline for textual output before it reaches the user interface layer.

## 2. Public API & Interfaces
| Entity | Type | Description |
| :--- | :--- | :--- |
| OutputPrinter | Class | Manages how LLM output tokens are printed to the console based on the print mode. |
| __init__ | Method | Initializes the OutputPrinter with a specific printing mode and token limit. |
| process_and_print | Method | Processes a single formatted token and prints it based on the configured mode. |
| flush_buffers | Method | Prints any remaining content in buffers at the end of the stream. |
| process_token | Method | Processes a single formatted token and returns the string to be printed, or None if nothing is ready to be printed yet (due to buffering). |
| flush | Method | Returns any remaining content in buffers at the end of the stream. |

## 3. Implementation Details & Side Effects
- **Core Logic:** The component uses a state machine defined by `self.print_mode`. Token processing involves accumulating tokens into `line_buffer` or `token_buffer` while incrementing `buffered_token_count`. Printing occurs only when a condition is met: encountering a newline (`\n`) for line modes, or exceeding `tokens_per_print` for token modes. The `line_or_x_tokens` mode prioritizes newline detection, resetting the count upon line completion, otherwise it checks the token threshold.
- **Side Effects:** It interacts with external state via `func.out` (printing to console) and `func.log` (logging warnings).
- **Error Handling:** If an unrecognized `print_mode` is provided during initialization, `process_token` catches this condition, logs a warning via `func.log`, and defaults the behavior to printing tokens immediately (acting as if the mode were 'token').
