## 1. Overview & Purpose
| Component | Source File |
| :--- | :--- |
| ResponseParser | /ai/agents/response_parser.md |

This component is responsible for ingesting raw, unstructured text output generated by a large language model (LLM) and transforming it into a predictable, structured Python dictionary. Its primary responsibility is to parse proprietary communication protocols, specifically the JARVIS Plain Text Protocol (marked by `y `____@` tokens), ensuring robustness against common formatting inconsistencies introduced by generative models.

It functions as a critical service layer within the application's data ingestion pipeline. It sits downstream from the LLM interaction layer, acting as the translator between the model's natural language/semi-structured output and the application's internal state management system, which relies on standardized data structures for further processing by components like [ai/agents/response_parser.md].

## 3. Implementation Details & Side Effects
- **Core Logic:** The parsing process first splits the raw string using a regex token pattern (`____@`). It then iterates through these tokens to extract specific fields like `thought`, `notes`, and `response_to_user`. It employs specialized helper methods: `_parse_key_value_block` handles simple key:value pairs (Manifest), while `_parse_tool_block` extracts complex tool definitions, including sanitizing YAML arguments via `_sanitize_yaml` to correct model-specific formatting errors like unquoted variables and indentation drift.

- **Side Effects:** The component uses `ai.functions.log` internally when tool parsing fails, indicating interaction with a logging mechanism.

- **Error Handling:** It wraps the entire parsing logic in a top-level `try...except` block, returning a standardized `{"status": "FAILED", "error": "..."}` dictionary upon any unexpected exception. The `_parse_tool_block` also contains specific exception handling for YAML parsing failures.
