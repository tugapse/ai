## The AI folder

JARVIS keeps its config, templates, sessions, memory and logs in one folder: the **AI folder**
(called `<root>` or "AI dir" in the code and the rest of this guide).

By default it's `~/Ai` (`$HOME/Ai` on Linux, `%USERPROFILE%\Ai` on Windows). To use another
folder, set the `AI_ASSISTANT_DIRECTORY` environment variable:

```bash
export AI_ASSISTANT_DIRECTORY="/path/to/my/ai-folder"     # put this in your shell profile
```

A typical AI folder after some use:

```
<root>/
├── config.json             # your settings (see below)
├── system/                 # the app's defaults, kept up to date by JARVIS
│   ├── config/             #   mcp_config.json (shipped MCP servers, disabled)
│   ├── inject/             #   text blocks inserted into prompts
│   ├── models/             #   model configs shipped with the app
│   ├── pipelines/          #   default, small, multi
│   ├── system-prompt/      #   system prompts (chat and agents)
│   ├── knowledge/          #   projects.json: knowledge registered per folder   (created later)
│   ├── logs/               #   logs                                             (created later)
│   ├── frontend/           #   cached web UI versions                           (created later)
│   └── workspace/          #   default folder for agents started from the web  (created later)
├── user/                   # yours: copied once, never touched again
│   ├── config/             #   your mcp_config.json (merged over the system one)
│   ├── models/             #   your model configs (win over system/models)
│   ├── pipelines/          #   your pipelines (win over system/pipelines)
│   ├── task/               #   tasks for --task
│   ├── tools/              #   your Python tools
│   └── server/             #   devices.json: paired devices                     (created later)
├── databases/              # long-term memory (vector DB)
├── knowledge/<project>/    # knowledge generated by ai knowledge build
└── sessions/
    ├── agents/             # agent sessions, one folder per working directory
    ├── chat/               # /save and /load in the plain chat
    └── server/             # chat sessions from the server / web UI
```

## How templates are copied

The defaults live in the repo at `assets/templates/` (`system/` and `user/`).

- **First run** (no `config.json` yet): JARVIS copies the templates into the AI folder and writes a
  new `config.json`.
- **`system/` on every run**: JARVIS compares each shipped file with your copy and updates it when
  the app ships a new version (`ai.template_sync`). A file you **edited** is first saved to
  `system/backup/<date>/`, and a warning names it. `system/.templates.json` records what was written
  last time, which is how JARVIS tells an untouched file from an edited one. Files that aren't
  shipped (your own models in `system/models/`, logs, sessions…) are left alone.
- **`user/`**: copied once; files that exist are **never overwritten**.
- **`ai config reset`**: writes a fresh `config.json` with the defaults (your settings are
  dropped) and copies any `user/` template files that are **missing**.

So anything you customise should live in `user/` (looked up first), or in a file with a new name in
`system/`. Edits to shipped files in `system/` are replaced on the next update (with a backup).

> Tip: to try template changes without touching your real setup, point
> `AI_ASSISTANT_DIRECTORY` at a fresh, empty folder for that run.

## Where JARVIS looks for each thing

| Thing | Flag / setting | Looked up in (first match wins) |
|-------|----------------|---------------------------------|
| Model config | `--model`, `MODEL_CONFIG_NAME` | `user/models/` → `system/models/`. Subfolders are allowed: `--model agents/lite`. `.json` is optional. |
| Pipeline | `--pipeline` | path as given → `user/pipelines/` → `system/pipelines/` |
| Agent system prompt | `prompt_file` in a pipeline | `user/system-prompt/` → `system/system-prompt/` (or an absolute path) |
| Chat system prompt | `--system`, `--system-file`, `SYSTEM_PROMPT_FILE` | see [System prompts](#system-prompts) |
| Task | `--task` | `user/task/` (subfolders allowed: `--task code/extract-knowledge`) |
| MCP servers | — | `system/config/mcp_config.json`, merged with `user/config/mcp_config.json` (user wins per server) |
| Your tools | — | `user/tools/*.py` |
| Agent sessions | `ai agent --resume`, `ai agent --session-id` | `sessions/agents/<folder id>/` (moved from `system/logs/agents/` on first use) |

## config.json

`config.json` sits at the root of the AI folder. JARVIS reads it on startup and fills in a few
defaults (model, system prompt, approvals, paths) the first time. Any setting from the
[reference](#settings-reference) can be added by hand; settings that aren't there use their default.

A small example:

```json
{
    "MODEL_CONFIG_NAME": "agents/qwen36-35b-gguf",
    "HIL_TOOLS": ["execute_command", "write_file", "patch_file", "delete_file"],
    "LTM_SCOPE": "project",
    "KNOWLEDGE_EXTENSIONS": ["py", "ts"],
    "SERVER_PORT": 9999,
    "TOOLS_WEB_ENABLED": false
}
```

Command-line flags win over `config.json` for that run (e.g. `--model`, `--system`, `--no-out`).

`<root_dir>` inside `config.json` is replaced by the AI folder path when it's loaded.

## System prompts

The system prompt is the first message the model sees: its personality and rules.

- **Agents** get theirs from the pipeline: each agent has a `prompt_file`, relative to
  `system/system-prompt/` (e.g. `agents/jarvis.md`, `agents/small/engineer.md`).
  The app adds the tool list and the output rules (`{{TOOLS}}`, `{{AGENT_OUTPUT_RULES}}`).
- **Chat and one-shot messages** use, in order:
  1. `--system-file PATH` — any file;
  2. `--system NAME` — `NAME.md` inside the system prompts folder (`PATHS_SYSTEM_TEMPLATES`,
     default `system/system-prompt/`), e.g. `--system chat/default`;
  3. `SYSTEM_PROMPT_FILE` from `config.json` (default `default` → `system/system-prompt/default.md`),
     resolved the same way;
  4. if the name is `default` and the file is missing or empty: *"You are a helpful AI assistant."*

The shipped `default.md` and `chat/default.md` hold the same short JARVIS chat prompt (helpful,
direct, answers in your language, no invented facts). To change it, put your own `default.md` in
`user/system-prompt/`, or point `SYSTEM_PROMPT_FILE` / `--system-file` at another file.

## Tasks

A task is a prompt template: a Markdown file with instructions, run with `--task NAME`.

```bash
./run.sh -f app.py -t create-comment -o app.commented.py
git diff --staged | ./run.sh -t commit
./run.sh -t release/start
```

- JARVIS reads `user/task/NAME.md`, then appends whatever you piped in and your `--msg`.
- `--task-file PATH` does the same with any file.
- With `ai agent`, the task becomes the agent's first message.

Writing your own: create `user/task/my-task.md` with plain instructions, e.g.

```markdown
Explain the following code to a junior developer. Use short paragraphs and one example.
```

then run `./run.sh -f thing.py -t my-task`.

Tasks shipped with the app:

| Task | What it does |
|------|--------------|
| `commit` | Commit message from a `git diff` |
| `create-changelog` | Changelog entry |
| `create-comment` | Adds doc comments to a source file without changing the code |
| `release/start`, `finish-release` | Release helpers |
| `code/extract-knowledge` | Component JSON for one file (used by `ai knowledge build`) |
| `code/create-code-documentation` | Markdown doc for one file (used by `ai knowledge build`) |

## Inject templates

`system/inject/` holds blocks of text (`agent-out.md`, `plan.md`, `thinking.md`, `thought.md`) that
are inserted into prompts. `agent-out.md` is the agent output format (the XML the model must answer
with) and is added to every agent prompt.

For chat prompts there's a generic mechanism: an `INJECT_TEMPLATES` list in `config.json` replaces a
placeholder with the content of a file from `PATHS_INJECT_TEMPLATES`:

```json
{
    "PATHS_INJECT_TEMPLATES": "<root_dir>/system/inject",
    "INJECT_TEMPLATES": [ { "key": "{{THINKING}}", "value": "thinking" } ]
}
```

Neither is set by default.

## Settings reference

Defaults marked *auto* are written to `config.json` on first run. "Installed" means "on when the
matching engine is installed with `ai install`".

### General

| Setting | Default | Description |
|---------|---------|-------------|
| `MODEL_CONFIG_NAME` | `default.json` *auto* | Model config to use (see [Where JARVIS looks](#where-jarvis-looks-for-each-thing)). |
| `SYSTEM_PROMPT_FILE` | `default` *auto* | Chat system prompt. |
| `PATHS_SYSTEM_TEMPLATES` | `<root>/system/system-prompt` | Folder used by `--system` and `SYSTEM_PROMPT_FILE`. |
| `PATHS_LOGS` | `<root>/logs` *auto* | Log folder. |
| `PATHS_WORKSPACES` | `<root>/workspaces` *auto* | Workspaces folder. |
| `PATHS_INJECT_TEMPLATES` | — | Folder for `INJECT_TEMPLATES`. |
| `INJECT_TEMPLATES` | `[]` | `[{ "key", "value" }]` placeholder replacements in chat prompts. |
| `ROOT_DIRECTORY` | the AI folder *auto* | Set on every start; don't edit. |

### Output

| Setting | Default | Description |
|---------|---------|-------------|
| `PRINT_LOG` | `false` | Show logs (`--print-log`). |
| `PRINT_DEBUG` | `false` | Show debug logs (`--print-debug`). |
| `PRINT_OUTPUT` | `true` | Print answers (`--no-out` turns it off). |
| `THINKING_MODE` | `progressbar` | How the "thinking" animation is shown. |
| `ENABLE_THINKING_DISPLAY` | `true` | Show the thinking animation (`--no-think-anim`). |
| `TOKENS_PER_PRINT` | `50` | Tokens buffered before printing. |

### Agents

| Setting | Default | Description |
|---------|---------|-------------|
| `HIL_TOOLS` | `execute_command`, `write_file`, `patch_file`, `delete_file` *auto* | Tools that need your approval. |
| `AGENT_THOUGHT` | `false` *auto* | Show the agents' reasoning (`/thoughts` toggles it). |
| `AGENT_TOOL_CATEGORIES` | `true` | Agents see tool categories and open them with `open_tools`; `false` lists every tool. |
| `AGENT_TOOL_RESULT_MAX_CHARS` | `12000` | Longest tool result put in an agent's context (0 = no limit). |
| `TOOLS_FILESYSTEM_ENABLED` | `true` | Built-in file tools. |
| `TOOLS_SEARCH_ENABLED` | `true` | Built-in search tools. |
| `TOOLS_SHELL_ENABLED` | `true` | Built-in shell tool. |
| `TOOLS_WEB_ENABLED` | `true` | Built-in web search/read tools. |
| `TOOLS_NOTIFY_ENABLED` | `true` | Desktop notifications. |

### Knowledge

| Setting | Default | Description |
|---------|---------|-------------|
| `KNOWLEDGE_ENABLED` | `true` | Knowledge module. |
| `KNOWLEDGE_SOURCES` | `[]` | Extra sources for every project: paths or `{"id", "path", "kind": "auto\|knowledge\|docs"}`. |
| `KNOWLEDGE_OUTPUT_DIR` | `<root>/knowledge` | Where `ai knowledge build` writes. |
| `KNOWLEDGE_EXTENSIONS` | `["py"]` | Source extensions to document. |
| `KNOWLEDGE_AUTO_UPDATE` | `true` | Regenerate the knowledge of files an agent changed. |
| `KNOWLEDGE_AUTO_UPDATE_MAX` | `5` | Max files regenerated per run. |
| `KNOWLEDGE_SEMANTIC` | installed | Embedding search for knowledge (keyword search otherwise). |
| `KNOWLEDGE_INJECT_TOP_K` | `4` | Components added to each agent step (0 = off). |
| `KNOWLEDGE_INJECT_MAX_CHARS` | `1500` | Size budget for that. |

### Long-term memory

| Setting | Default | Description |
|---------|---------|-------------|
| `VECTOR_MEMORY_ENABLED` | installed | Long-term memory. |
| `VECTOR_DB_PATH` | `<root>/databases` *auto* | Memory database folder. |
| `LTM_SCOPE` | `project` | `project`, `session` or `global`. |
| `LTM_INJECT_TOP_K` | `4` | Memories added to each agent step (0 = off). |
| `LTM_MIN_RELEVANCE` | `0.3` | Minimum similarity for a memory to be added. |
| `LTM_AUTO_REFLECT_MIN` | `15` | New memories that trigger a reflection at the end of a run (0 = off). |
| `LTM_LLM_IMPORTANCE` | `false` | Ask the model to rate each memory (slower) instead of rating by type. |
| `VECTOR_RECENCY_WEIGHT` / `VECTOR_IMPORTANCE_WEIGHT` / `VECTOR_RELEVANCE_WEIGHT` | `1.0` | How memories are ranked. |

### Voice

| Setting | Default | Description |
|---------|---------|-------------|
| `VOICE_ENABLED` | `false` *auto* | Speak the answers (needs the voice engine). |
| `VOICE_FILE` | `pt-Spk1_man` | VibeVoice voice file in `assets/voices/` (without `.pt`). |

### Server

| Setting | Default | Description |
|---------|---------|-------------|
| `SERVER_HOST` | `0.0.0.0` | Address the Brain Server listens on (all interfaces; `127.0.0.1` for this machine only). |
| `SERVER_PORT` | `9999` | Port. |
| `SERVER_TRUSTED_NETWORKS` | localhost, private LAN, Tailscale (`100.64.0.0/10`) | Networks allowed to use the server (every route). |
| `SERVER_ALLOWED_ORIGINS` | `localhost:4200` | Browser origins allowed by CORS. |
| `SERVER_RELAY_URL` | — | Brain Server for relay mode (same as `ai server --relay`). |
| `SERVER_AGENT_WORKDIR` | `<root>/system/workspace` | Default folder for agents started from the web. |
| `SERVER_FRONTEND_DIR` | — | Folder with a jarvis-web build; wins over the bundled one. |
| `SERVER_FRONTEND_VERSION` | bundled | Cached web UI version to serve (`ai server frontend use`). |
| `SERVER_TOTP_ENABLED` | `false` | Require authenticator codes (run `ai server totp-setup` first). |
| `SERVER_TOTP_TOOLS` | `execute_command`, `delete_file` | Tools whose approval needs an authenticator code. |

### Internal

`DEFAULTS_MIGRATION` (last config migration applied) and `PRINT_MODE` (set on every start) are
managed by the app.
