## 1. Overview & Purpose
| Component | Source File |
| :--- | :--- |
| **SpecialistManager** | [src/ai/agents/specialist_manager.py](/AgentDocs/ai/agents/specialist_manager.md) |

The `SpecialistManager` is responsible for managing and invoking specialized LLM workers designed for high-complexity, unstructured generation tasks. It is specifically utilized when a task requires deep context, such as writing new files or patching existing code, where a standard agent might lack the necessary focus or role-specific prompting.

Within the broader application architecture, this component acts as a specialized execution layer for tools that require a dedicated persona. It bridges the gap between high-level tool requests and raw LLM generation by providing task context (including file state) and enforcing strict output constraints to ensure the resulting text is usable for automated file operations.

## 2. Public API & Interfaces

| Entity | Type | Description |
| :--- | :--- | :--- |
| `SpecialistManager` | Class | Manages specialist LLM invocations based on a provided configuration mapping tools to roles. |
| `__init__(connector, specialist_config)` | Constructor | Initializes the manager with an LLM `connector` and a dictionary mapping tool names to role descriptions. |
| `is_specialist_tool(tool_name)` | Method | Returns `True` if the provided `tool_name` exists within the specialist configuration. |
| `invoke(tool_name, params)` | Method | Executes a specialist request. Takes a tool name and a parameter dictionary (containing `instructions`/`content` and `path`), reads the target file's current state, and returns the raw text generated by the specialist. |

## 3. Implementation Details & Side Effects
- **Core Logic:** The `invoke` method performs a context-gathering step before calling the LLM. It attempts to resolve the target file path using `_resolve_path` and reads the first 3000 characters of the existing file to provide "Current State" context. It then constructs a payload containing the file path, the current state, and the user's goal, instructing the model to output raw text without markdown formatting.
- **Side Effects:** 
    - **Filesystem:** Performs read operations on the local filesystem to retrieve file content for context.
    - **Network/LLM:** Sends a request to an external or local LLM via the provided `connector`.
- **Error Handling:** The file reading process is wrapped in a broad `try-except` block. If the file does not exist, cannot be read, or the path is invalid, the system silently defaults the `current_state` to a placeholder string ("File does not exist yet or is empty.") and continues execution.
