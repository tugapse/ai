## 1. Overview & Purpose
| Component | Source File |
| :--- | :--- |
| **SpecialistManager** | [src/ai/agents/specialist_manager.py](/src/ai/agents/specialist_manager.py) |

The `SpecialistManager` is responsible for managing and invoking specialized LLM workers designed for high-complexity, unstructured generation tasks. It specifically targets operations that require deep context, such as writing new files or patching existing code, which may exceed the capabilities of general-purpose agents.

Within the broader architecture, this component acts as a specialized execution layer. It bridges the gap between high-level tool requests and raw LLM generation by providing the necessary file context (current state) and role-specific instructions to a connector, ensuring the specialist model produces precise, raw text output suitable for file system operations.

## 2. Public API & Interfaces

| Entity | Type | Description |
| :--- | :--- | :--- |
| `SpecialistManager` | Class | Manages specialist LLM invocations using a provided connector and a configuration mapping tool names to roles. |
| `__init__(connector, specialist_config)` | Constructor | Initializes the manager with an LLM connector and a dictionary mapping tool names to role descriptions. |
| `is_specialist_tool(tool_name)` | Method | Returns `True` if the provided `tool_name` exists within the specialist configuration. |
| `invoke(tool_name, params)` | Method | Executes a specialist task. It resolves the target file path, reads up to 3000 characters of the current file state, and returns the raw text generated by the specialist. |

## 3. Implementation Details & Side Effects
- **Core Logic:** When `invoke` is called, the manager attempts to resolve the target file path using `_resolve_path`. If the file exists, it reads the first 3000 characters to provide "Current State" context. It then constructs a payload containing the file path, the current state, and the user's goal (extracted from `instructions`, `content`, or `replace` parameters). This payload is sent to the `connector` with a specific system prompt derived from the `specialist_config`.
- **Side Effects:** 
    - **Filesystem:** Performs read operations on the local filesystem to retrieve file context.
    - **Network/LLM:** Makes external calls via the `connector.send_raw_request` method to interact with LLM models.
- **Error Handling:** The file reading process is wrapped in a broad `try-except` block. If a file cannot be read (e.g., due to permissions or path errors), the manager silently falls back to a default state string ("File does not exist yet or is empty.") without raising an exception.
