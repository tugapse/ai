## 1. Architectural Role

**Functional Mission**
The **ResponseParser** is a specialized utility designed to transform unstructured or semi-structured XML strings generated by Large Language Models (LLMs) into structured, actionable Python dictionaries. Its primary mission is to enforce schema integrity on LLM outputs, specifically handling the extraction of reasoning (thought), metadata (manifest), tool execution instructions (action), and user-facing communication (response_to_user), while providing a robust "salvage" mechanism to repair malformed XML caused by rogue characters within text blocks.

**System Context & Integration**
This component acts as a critical data-sanitization layer within the agentic workflow, positioned between the raw LLM output and the downstream execution modules. By converting string-based XML into typed dictionaries, it enables the system to programmatically trigger tool calls and manage agent state. It serves as a specialized implementation or sibling to the broader parsing logic described in [/docs/agents/response_parser.md](/docs/agents/response_parser.md), ensuring that the transition from "text generation" to "system action" is reliable and error-resistant.

## 2. Environment & Configuration
**Environment Lookups:**
- `parameter_mode` (via `__init__`)  Determines whether tool parameters are parsed as raw XML child nodes or as a JSON-encoded string.

**Hardcoded Constants:**
- `parameter_mode` (Default: `"xml"`)  The default parsing strategy for tool parameters.

## 3. Interface & API Surface
| Entity | Type | Functional Responsibility |
| :--- | :--- | :--- |
| `ResponseParser` | Class | Orchestrates the parsing, sanitization, and extraction of XML-structured LLM responses. |
| `__init__` | Method | Initializes the parser with a specific `parameter_mode`. |
| `_extract_params` | Method | Internal logic to parse `tool_parameters` based on the selected `parameter_mode` (JSON vs XML). |
| `_sanitize_block` | Method | Performs regex-based extraction and character escaping (e.g., `<` to `&lt;`) to repair broken XML tags. |
| `parse` | Method | The primary entry point; executes the full pipeline from raw string to structured dictionary. |

## 4. Execution Logic & Flow
- **Initialization**: The `ResponseParser` is instantiated, setting the `parameter_mode` to either `"xml"` or `"json"`.
- **Data Path**: 
    1. **Boundary Detection**: The `parse` method locates `<response>` and `</response>` tags within the input string.
    2. **Strict Parsing**: The system attempts to parse the extracted block using `xml.etree.ElementTree`.
    3. **Salvage (If Required)**: If strict parsing fails, the `_sanitize_block` method is called sequentially for `thought`, `notes`, and `response_to_user` tags to escape illegal characters.
    4. **Extraction**: Once parsed, the method traverses the tree to extract `manifest`, `action` (including `tool_name`, `tool_parameters`, and `agent_target`), and text content.
    5. **Output**: Returns a dictionary containing `status`, `thought`, `notes`, `manifest`, `action`, and `response_to_user`.
- **Conditional Branching**:
    - **Missing Boundaries**: If `<response>` tags are absent, returns `status: FAILED`.
    - **JSON Mode**: If `parameter_mode` is `"json"`, `_extract_params` attempts `json.loads()`; failure returns an error key.
    - **Parse Failure**: If both strict and salvage attempts fail, returns `status: FAILED` with the specific `ET.ParseError`.
