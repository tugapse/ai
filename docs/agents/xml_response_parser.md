## 1. Architectural Role
The [xml_response_parser.py](src/ai/agents/xml_response_parser.py) serves as a specialized data extraction layer designed to deserialize structured XML responses generated by Large Language Models (LLMs). Its primary responsibility is to transform raw, potentially malformed string outputs into a validated, typed dictionary containing thoughts, manifest data, tool actions, and user-facing responses. It implements a robust "salvage" mechanism using regex-based sanitization to repair XML syntax errors caused by rogue characters within LLM-generated text blocks, ensuring system stability during agent execution.

**Hardcoded Constants:**
- `parameter_mode` (Default: `"xml"`)  Determines if tool parameters are parsed as raw XML child nodes or as a JSON string.

## 3. Interface & API Surface
| Entity | Type | Functional Responsibility |
| :--- | :--- | :--- |
| `ResponseParser` | Class | Orchestrates the parsing and sanitization logic for LLM XML outputs. |
| `__init__` | Method | Initializes the parser with a specific `parameter_mode`. |
| `_extract_params` | Method | Extracts and converts tool parameters from an XML element based on the selected mode. |
| `_sanitize_block` | Method | Uses regex to locate specific tags and escapes `<` or `>` characters to prevent XML parse errors. |
| `parse` | Method | The primary entry point; executes the multi-stage parsing (Strict $\rightarrow$ Salvage $\rightarrow$ Final) flow. |

## 4. Execution Logic & Flow
- **Initialization**: The `ResponseParser` instance is created, setting the `parameter_mode` (either `xml` or `json`).
- **Data Path**: 
    - **Input**: A raw `str` containing an XML envelope (expected `<response>` boundaries).
    - **Processing**: 
        1. Locates `<response>` and `</response>` boundaries.
        2. Attempts strict parsing via `xml.etree.ElementTree`.
        3. **If ParseError occurs**: Triggers salvage logic; `_sanitize_block` is called for `thought`, `notes`, and `response_to_user` tags to escape illegal characters.
        4. Re-attempts parsing the sanitized string.
        5. Traverses the resulting DOM tree to extract structured fields (`manifest`, `action`, etc.).
    - **Output**: A `Dict[str, Any]` containing a `status` key ("SUCCESS" or "FAILED") and the extracted payload.
- **Conditional Branching**:
    - **Boundary Check**: If `<response>` tags are missing, returns "Missing response boundaries".
    - **Mode Switch**: Inside `_extract_params`, logic branches between `json.loads` and XML child-node iteration.
    - **Error Handling**: Multiple `try-except` layers catch `ET.ParseError` (salvage attempt) and generic `Exception` (system failure).
