## 1. Architectural Role

**Functional Mission**
The **ThinkingLogManager** is a specialized utility designed to provide persistent, thread-safe logging of internal "reasoning" or "thinking" processes generated by AI agents. Its primary mission is to capture the non-output cognitive steps of a modeloften stripped from final user responsesand store them in structured log files, ensuring that these traces are preserved for debugging, auditing, or observability purposes without interfering with the primary communication stream.

**System Context & Integration**
This component acts as a sidecar logging service that integrates with the broader execution flow by intercepting raw thought strings. It interacts heavily with the system's configuration layer via [config.md](/docs/config.md) to determine appropriate storage paths. By implementing a file-based locking mechanism, it ensures that multiple concurrent processes or asynchronous agent tasks can write to the same log files without data corruption. It serves as a critical data sink for modules that require high-fidelity visibility into the model's internal state transitions.

## 2. Environment & Configuration

**Environment Lookups:**
- `ProgramConfig.current.get(ProgramSetting.PATHS_LOGS)`  Retrieves the base directory for all system logs to determine the root for thinking logs.

**Hardcoded Constants:**
- `DEFAULT_LOG_SUBDIR` (Default: `"Ai/logs/thinking"`)  The fallback relative path for log storage if no configuration is found.
- `DEFAULT_FILENAME` (Default: `"thinking_process.log"`)  The fallback filename for the primary thinking log.
- `max_lock_wait_time` (Default: `10`)  Maximum seconds to attempt acquiring a file lock before raising a `TimeoutError`.
- `lock_poll_interval` (Default: `0.1`)  The delay in seconds between attempts to acquire a file lock.

## 3. Interface & API Surface

| Entity | Type | Functional Responsibility |
| :--- | :--- | :--- |
| `ThinkingLogManager` | Class | Orchestrates log file creation, directory management, and synchronized write operations. |
| `_acquire_write_lock` | Method | Implements a spin-lock mechanism using `os.O_EXCL` to ensure exclusive file access. |
| `_release_write_lock` | Method | Removes the `.lock` file to allow subsequent write operations. |
| `write_thinking_log` | Method | Appends raw content to both the specific session log and the global active log file. |
| `write_session_header` | Method | Writes a timestamped session delimiter to the log files, resetting the active log via "w" mode. |
| `read_thinking_log` | Method | Retrieves the full content of the current thinking log as a string. |

## 4. Execution Logic & Flow

- **Initialization**: 
    1. Sanitizes the provided `log_file_name` by replacing spaces with underscores and ensuring a `.log` extension.
    2. Attempts to resolve the log directory via `ProgramConfig`.
    3. Falls back to the user's home directory and `DEFAULT_LOG_SUBDIR` if configuration is unavailable.
    4. Creates the target directory if it does not exist.
    5. Defines paths for the specific log file, a global `active_thinking_process.log`, and a `.lock` file.
- **Data Path**: 
    - **Input**: String content (thought process) or tags (session metadata).
    - **Processing**: 
        1. Acquire lock $\rightarrow$ 2. Open file in append mode $\rightarrow$ 3. Write content $\rightarrow$ 4. Release lock.
    - **Output**: Persistent text appended to `.log` files on the filesystem.
- **Conditional Branching**:
    - **Lock Acquisition**: If `os.open` fails with `errno.EE_EXIST`, the system enters a retry loop until `max_lock_wait_time` is exceeded, at which point a `TimeoutError` is raised.
    - **Config Availability**: If `ProgramConfig.current` is `None`, the logic branches to use the hardcoded default pathing.
    - **Error Handling**: `write_thinking_log` and `write_session_header` catch `TimeoutError` and `IOError` to prevent logging failures from crashing the main execution thread.
