## 1. Architectural Role
|  |  |
| :--- | :--- |
| Name | App Factory |
| Source file | app.py |

The **app.py** component serves as the central orchestration point for the FastAPI web server, responsible for bootstrapping the "JARVIS Neural Hub" API. It acts as a dependency injection container, initializing and wiring critical service layerssuch as session management, prompt management, and chat servicesinto the application state to ensure a unified execution context.

**Functional Mission**
The primary mission of **app.py** is to construct a fully configured FastAPI instance that integrates business logic, routing, and middleware. It solves the problem of service lifecycle management by centralizing the instantiation of managers and services, ensuring that the web layer has direct, stateful access to the underlying AI capabilities and data persistence layers.

**System Context & Integration**
This component sits at the entry point of the server module, acting as the bridge between the raw HTTP interface and the core AI logic. It integrates external routers for session and prompt management and delegates complex conversational logic to the [ChatService](/docs/ai/modules/server/services/chat.md). By mounting a static frontend and applying custom middleware, it transforms the backend logic into a complete, accessible web application. It relies heavily on the [BrainHub](/docs/ai/modules/server/brain_hub.md) to provide the intelligence required for chat completions.

## 2. Environment & Configuration
**Environment Lookups:**
- `func.get_root_directory()`  Retrieves the base filesystem path for locating sessions and system directories.

**Hardcoded Constants:**
- `SESSION_ROOT_DIR` (Default: `Path(func.get_root_directory()) / "sessions" / "server"`)  The filesystem location for session data.
- `PROMPT_ROOT_DIR` (Default: `Path(func.get_root_directory()) / "system"`)  The filesystem location for system prompts.

## 3. Interface & API Surface
| Entity | Type | Functional Responsibility |
| :--- | :--- | :--- |
| `create_app` | Func | Factory function that initializes the FastAPI app, wires dependencies, and mounts static files. |
| `chat_completions` | Func | API endpoint (`/api/v1/chat/completions` or `/api/v1/chat`) that processes AI chat requests via `ChatService`. |
| `health` | Func | API endpoint (`/api/health`) that returns the current operational status and model name. |

## 4. Execution Logic & Flow
- **Initialization**:
    1. Define root directories for sessions and prompts using `func.get_root_directory()`.
    2. Instantiate the `FastAPI` application.
    3. Include routers for sessions and prompts.
    4. Instantiate `SessionManager`, `PromptManager`, and `ChatService`.
    5. Attach these services to `app.state` for global access within the request lifecycle.
- **Data Path (Chat Completion)**:
    1. **Input**: Receives a `ChatCompletionRequest` via POST.
    2. **Processing**: Logs the request details via `func.debug` and invokes `chat_service.chat_completion(payload)`.
    3. **Output**: Returns the result (streaming or non-streaming) generated by the `ChatService`.
- **Conditional Branching**:
    - **Frontend Check**: If a `frontend` directory exists relative to the file, it mounts the directory as a static application at the root path `/`.
    - **Service Validation**: In `chat_completions`, if `chat_service` is `None`, it raises an `HTTPException` (500).
    - **Health Check Logic**: If `brain_hub` is present, it attempts to retrieve the model name from `brain_hub.get_stats()`; otherwise, it defaults to "JARVIS".
