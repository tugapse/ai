## 1. Architectural Role

**Functional Mission**
The **SpeechBridge** class serves as a specialized text-to-speech preprocessing layer designed to sanitize and optimize raw text streams for auditory consumption. Its primary mission is to intercept text generated by the systemspecifically filtering out non-auditory elements like Markdown syntax, code blocks, and list markersand transforming technical strings (such as file paths) into natural language equivalents to ensure a seamless verbal user experience.

**System Context & Integration**
This component acts as a middleware buffer between the core logic/LLM outputs and the voice synthesis engine. It receives raw text via the `feed` method, manages state regarding whether the current stream is inside a code block, and buffers text until complete sentences are formed. Once a sentence is identified, it passes the cleaned, "voice-ready" string to a voice module, typically an implementation of [base_module](/docs/modules/base_module.md) or [vibe_module](/docs/modules/voice/vibe_module.md), ensuring that the auditory output remains coherent and free of technical clutter.

- `sentence_regex` (re.Pattern): A compiled regular expression used to identify sentence boundaries for optimal speech chunking.

| `abort` | Method | Clears all buffers and signals the voice module to cease current operations. |

## 4. Execution Logic & Flow

- **Initialization**: The component sets up an empty string `buffer`, a boolean `in_code_block` flag, and a list of `code_announcements`. It requires a `voice_module` object capable of responding to `process_token` and `abort`.
- **Data Path**: 
    1. **Input**: Raw text is passed to `feed()`.
    2. **Code Block Detection**: If ` ``` ` is detected, the `in_code_block` state toggles. If entering a code block, a random announcement is sent to the voice.
    3. **Sanitization**: If not in a code block, text is passed to `_process_text_chunk()`, where Markdown headers (`#`), bold/italic markers (`*`), and list markers are stripped via regex.
    4. **Path Transformation**: File paths are identified via regex and transformed into natural language via `_replace_path_for_voice`.
    5. **Buffering**: Cleaned text is appended to `self.buffer`.
    6. **Sentence Splitting**: The `sentence_regex` scans the buffer. When a sentence terminator is found, the completed sentence is sliced from the buffer.
    7. **Output**: The sliced sentence is passed to `_send_to_voice()`, which removes remaining backticks and calls `self.voice.process_token()`.
- **Conditional Branching**: 
    - If `in_code_block` is `True`, text is swallowed without being sent to the voice module (to prevent the AI from reading code aloud).
    - If `debug` is `True`, the processed text is printed to the console using `func.out`.
